## 1. The honest headline

RAVQEN is a **web application**. This repository contains **no Android project,
no Capacitor/Tauri wrapper, no Gradle configuration and no signing setup**
(verified: no `android/` directory, no `*.gradle*` files, no
`AndroidManifest.xml`, no `capacitor.config.*`, no `tauri.conf.*` anywhere in
the repo).

Every statement in Play Console about an Android binary — targetSdk, minSdk,
versionCode, AAB signing, manifest permissions — is therefore **impossible to
verify from here** and is listed under BLOCKED in the readiness report, not
under READY. Nothing has been invented to fill that gap: no signing key has
been generated, and none should be generated by tooling.

## 3. The one decision that unblocks Parts 18–21

Pick an Android packaging route. The repo is agnostic; both are legitimate:

1. **Trusted Web Activity (TWA / Bubblewrap)** — lowest effort. Requires the
   site to keep passing PWA baselines and a `assetlinks.json` at
   `https://ravqen.freebuff.app/.well-known/assetlinks.json` signed with the
   upload key. Note for the author: with no service worker today, Chrome may
   not treat the site as installable, and Play's web-app quality bar expects
   offline tolerance or a native wrapper instead.
2. **Capacitor (or Tauri mobile)** — a real WebView shell: camera permission
   becomes a native manifest entry requested only when the scanner opens; the
   barcode path already degrades gracefully when `BarcodeDetector` is absent.

Either way, when the wrapper exists, before any Play submission:

- `targetSdkVersion >= 36` (Android 16), a conservative `minSdk`, a real
  incrementing `versionCode`, release signing via Play App Signing with the
  upload key held **outside** this repository
- permissions: camera only, runtime-requested only when the scanner sheet
  opens; no contacts/location/mic/storage/phone/SMS
- no debug builds, no debug logging, no test keys, no test Supabase project —
  production `VITE_SUPABASE_URL` and publishable key only

## 4. Store listing inputs (no fakes)

- **App name:** RAVQEN
- **Short description (≤80 chars):** "Sales, stock and cash records for Kenyan small businesses."
- **Full description:** must be written by a human who can stand behind it; the
  web landing page's copy is the honest starting point.
- **Screenshots:** must be captured from the real app (the verification suites
  already drive the real UI on a Pixel-class viewport); no staged or mocked
  screens. **MANUAL VERIFICATION REQUIRED.**
- **Feature graphic:** must be designed; the R-tile mark and the token palette
  in `src/styles.css` are the raw material. **MANUAL VERIFICATION REQUIRED.**
- **Content rating questionnaire:** no user-generated public content, no ads,
  financial/business tool — answer accordingly in Play Console.
- **Target audience:** adults running businesses; the app declares no children's
  data collection and the privacy policy commits to that.
- **Data safety form:** fill directly from §2's pointers —
  collected: name, email, optional phone, shop/business records, debtor
  contact details (user-entered), consent records; not collected: ad ID,
  location, contacts, device identifiers, children's data; data encrypted in
  transit (HTTPS), deletion path provided.

## 5. Reviewer access instructions (template — no real creds in repo)

When submitting, create a fresh reviewer account through the normal signup
flow, add a small demo shop, and paste the email + a password created **only
for the Play review** into the Play Console "App access" section. Rotate or
delete that account after review. Never commit these credentials anywhere.

## 6. What this repo will not do

- It will not generate or store a signing key.
- It will not fabricate screenshots, ratings, testimonials or download counts.
- It will not claim Play approval, legal compliance, or security guarantees.

The single remaining infrastructure step for the web product itself is the
Freebuff deploy (user presses Deploy in the Changes panel); this report does
not mark the live site re-verified until that happens.
